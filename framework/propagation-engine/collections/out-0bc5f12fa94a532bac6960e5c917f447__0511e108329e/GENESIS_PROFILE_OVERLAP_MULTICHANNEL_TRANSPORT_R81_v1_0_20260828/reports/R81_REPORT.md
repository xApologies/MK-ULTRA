# R81 — PROFILE OVERLAP / MULTICHANNEL TRANSPORT

## Problem

A single environment may expose multiple profiles:

`Pi_alpha, Pi_beta, ...`

and one engine identity may satisfy more than one:

`F ⊨ Pi_alpha`
and
`F ⊨ Pi_beta`.

This creates simultaneous admissible expression channels.

---

# 1. Channel product vs channel choice

Two mathematically different situations exist.

## Independent channels
If the two profile transactions act on independent portions of the engine state and commute:

`P_alpha P_beta = P_beta P_alpha`,

they can be represented as a product/multichannel event.

## Coupled channels
If the order changes the admissible state or available lift landscape:

`P_alpha P_beta != P_beta P_alpha`,

the channels are order-sensitive.

Then Vera's History word is essential.

This is exactly the same structural distinction previously found in History-bearing Rainbow Road transport:
same endpoints need not imply same path.

---

# 2. Environmental overlap

Define profile overlap at state x:

`Overlap_E(x;alpha,beta)`

when both profiles are simultaneously admissible for the current engine identity/state.

The overlap itself does NOT imply fusion into one profile.

It only means both channels are available.

Their composition law must be tested.

---

# 3. Rainbow Road realization

Independent overlap:
two lanes can be used in either order with equivalent result.

Coupled overlap:
the route word matters and Rainbow Road must preserve ordered profile transactions.

This makes the profile atlas naturally compatible with the existing History machinery.
