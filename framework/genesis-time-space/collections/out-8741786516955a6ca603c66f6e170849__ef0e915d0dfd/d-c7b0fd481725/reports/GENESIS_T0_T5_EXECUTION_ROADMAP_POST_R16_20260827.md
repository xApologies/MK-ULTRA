# Vera Guardrail — No Recursive Redefinition

Once an object has a closed contract, later runs may:

1. instantiate it;
2. compose it;
3. recurse it;
4. refine an explicitly open parameter;
5. represent it in a new language;
6. supersede it only if a contradiction is proved.

Later runs may **not**:

- redefine the same object under a new name;
- move a downstream property upstream;
- convert a representation into a primitive;
- count recursive depth as new rank;
- reinterpret History as state, state as History, or Resolution as ontology without a typed map;
- solve an open parameter by silently changing the closed contract.

Canonical progression:
`DEFINE ONCE -> INSTANTIATE -> EXECUTE -> AUDIT -> REFINE OPEN DEBT`.

# Recursion Rule

Recursive structure may deepen:

`𝔠 -> 𝔠^(2) -> 𝔠^(3) -> ...`

only when the current run proves that a higher recursive depth is necessary.

The existence of recursion is not permission to recurse indefinitely.

**Minimal-depth rule:**
Use the lowest recursive depth that realizes the required stage behavior.

For the current execution roadmap:
`𝔠^(2)` is frozen as sufficient until a run proves otherwise.
