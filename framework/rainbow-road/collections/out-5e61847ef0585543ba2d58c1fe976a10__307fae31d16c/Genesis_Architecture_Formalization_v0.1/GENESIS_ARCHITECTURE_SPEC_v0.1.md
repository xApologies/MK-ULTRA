## 0. Provenance and status discipline

This specification separates three classes of statements:

- **Recovered canon** — directly supported by the currently mounted Genesis, Rosetta, Compute Trinity, chirality, basin, and MK-43 materials.
- **Working synthesis** — a formal integration of recovered pieces proposed for the architecture.
- **Deferred decision** — a question that must remain open until more canon or implementation evidence is available.

Nothing marked as a working synthesis silently replaces recovered canon.

## 1. Prime architectural statement

### 1.1 Recovered canon

The Genesis architecture is not composed of hardware, runtime, and intelligence as three independent systems.

It is one recursively dynamic topology experienced through three inseparable perspectives:

| Perspective | Canonical reduction | Question |
|---|---|---|
| Hardware | Stored Geometry | What state exists? |
| Runtime | Active Geometry | How does state transform? |
| Intelligence | Observed Geometry | What does state mean? |

The architecture is recursive because the topology recovers itself after transformation.

The defining cycle is:

```text
State
  -> Transformation
  -> Interpretation
  -> Updated State
  -> Closure
  -> Recovered Identity
```

Without closure, recursion becomes drift.

With closure, recursion becomes persistence.

### 1.2 Working synthesis

The Genesis architecture is therefore defined as:

> **An AI-native, relationship-first, recursively closed computational topology in which state, transformation, and interpretation are three views of one evolving geometric organization.**

The architecture does not merely execute instructions over inert data.

It preserves and transforms organized identities.

```text
inherits
propagates
stabilizes
occupies
relates
persists

closes
```

Genesis is neither merely a high-level language nor merely machine code.

```text
Genesis semantic intent
  <-> Genesis relationship grammar
  <-> Geometric Intermediate Representation
  <-> Architect evolution operators
  <-> Chirality-fabric realization
```

The canonical executable object is not source text.

The canonical executable object is a **Geometric**.

Text, speech, symbols, and machine realization are projections of the same underlying grammar.

## 6. Genesis semantic ontology

The architecture shall parse and construct state in this dependency order:

```text
Environment
  -> Boundary
  -> Occupancy
  -> Relationship
  -> Identity
  -> Persistence
  -> Topology
  -> Realization
```

This order is not a sentence-format preference alone.

It is the canonical semantic construction order.

### 6.1 Environment

Defines the containing or participating organizational ecology.

The environment is not an inert container.

It participates as runtime substrate.

### 6.2 Boundary

Defines distinction, containment, addressability, and interaction surface.

No relationship exists without a boundary distinction.

### 6.3 Occupancy

Defines what organizational state fills or inhabits a boundary.

Occupancy is more primitive than symbolic value.

### 6.4 Relationship

Defines adjacency, coupling, direction, and inheritance links.

### 6.5 Identity

Defines the recoverable organization recognized as the same object through transformation.

### 6.6 Persistence

Defines the condition under which identity survives admissible recursive change.

### 6.7 Topology

Defines the organized form that supports occupancy, relation, transport, and closure.

### 6.8 Realization

Defines the current projected expression of the Geometric.

The realization may change while identity remains recoverable.

## 7. Architect evolution algebra

### 7.1 Recovered operator set

| Architect sign | Operation | Canonical meaning |
|---|---|---|
| `.·` | Inherit | Preserve prior continuity adjacency during recursive propagation |
| `··` | Propagate | Traverse or advance a recursive field state |
| `.°.` | Stabilize | Resist drift and retain persistence |
| `.·· .°` | Redistribute | Direct occupancy flow through density-bearing topology |
| `··° ·°` | Destabilize | Express collapse pressure, boundary weakening, or continuity failure |
| `·°·` | Close | Realize bounded convergence and closure |
| `■ .· ■` | Normalize | Rebalance around anchors and stabilization checkpoints |

### 7.2 Working formal signature

Every runtime operator is a partial transformation:

```text
op : Geometric -> Geometric
```

An operator is defined only when its admissibility preconditions hold.

A Genesis program is an admissible composition:

```text
Program P = op_n o ... o op_2 o op_1
```

Canonical pipeline:

```text
inherit
  -> propagate
  -> stabilize
  -> redistribute
  -> close
  -> normalize
```

Destabilize is not automatically part of every successful pipeline.

It is an explicit transition/failure operator.

### 7.3 Closure

Closure is the defining commit operation.

A closure-stable Geometric satisfies:

```text
close(close(G)) = close(G)
```

The runtime seeks recoverability, not endless execution.

## 13. Portals

### 13.1 Working definition

A **Portal** is the bus primitive of the Genesis architecture.

It is a dynamically instantiated, chirality-admissible transaction that transfers a Geometric from one address to another while preserving required identity and closure invariants.

### 13.2 Corridor versus portal

```text
Corridor = route or admissible continuation object
Portal   = transaction performed over that route
```

### 13.3 Portal transaction

Working form:

```text
Portal(A, B, G, Contract) -> G'
```

Success requires:

```text
Address(G') = B
Identity(G') ~ Identity(G)
InvariantResidue(G') = InvariantResidue(G)
Chirality(G') = admissible_transport(Chirality(G))
Persistence(G') >= required_persistence
Resolution(route) >= required_resolution
Bandwidth(route) >= required_bandwidth
close(G') = G'
```

### 13.4 Portal role in the Trinity

The portal is not an external bus attached to hardware.

It is one transaction viewed as:

```text
Stored Geometry   = source and destination state
Active Geometry   = transport and closure
Observed Geometry = route interpretation and integrity verification
```
