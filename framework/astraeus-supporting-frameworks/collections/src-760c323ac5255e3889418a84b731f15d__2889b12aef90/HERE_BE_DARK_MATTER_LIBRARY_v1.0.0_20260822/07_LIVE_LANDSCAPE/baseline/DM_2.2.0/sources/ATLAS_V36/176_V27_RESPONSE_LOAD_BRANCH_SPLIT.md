# 176 — Redistribution-Response vs Persistent Relational-Load Branches

## Purpose

V27's uniform-port theorem shows that the reduced Laplacian response can vanish while the hidden relationships themselves still exist.

The existing Atlas already contains a separate native energy-density family, so zero redistribution must not be silently interpreted as zero persistent load.

## 1. Branch A — realized redistribution response

On the fixed unsaturated support,

```text
deltaC_P = -Lambda c_P.
```

The hidden contribution is

```text
Delta(deltaC)_P = -DeltaLambda c_P.
```

This branch is state-contrast dependent and vanishes on uniform port states.

Its direct gravity route is

```text
DeltaLambda c_P
-> continuity perturbation difference
-> gravitational / TT admissibility
-> Time-Shell projection
-> Delta h
```

when the projection fiber separates the two states.

## 2. Branch B — persistent relational-capacity load

The recovered native energy family contains

```text
rho_E = Relationship * TransitionCapacity / ContainmentVolume.
```

Earlier clean Atlas work gave the finite heterogeneous candidate realization

```text
rho_E^R(U)
=
[ sum_{e in U} r_e T_e ] / nu_R(U),
```

where

```text
r_e
```

values the retained relationship and

```text
T_e
```

is an admissible realization of the native Transition-Capacity slot (v20 used runtime capacity as a candidate realization, not a final canonical identification).

This quantity depends on retained relationships/capacities, not on the instantaneous realized Laplacian flow.

Hence it is mathematically possible to have

```text
deltaC_P = 0
```

while

```text
rho_E^R(U) > 0.
```

Example: a persistent positive-capacity network at a uniform continuity state carries no realized edge response but still has nonzero relationship/capacity entries.

## 3. V27-T4 — Zero-flow does not imply zero-load

Under the existing two object definitions,

```text
realized redistribution = 0
```

does not logically imply

```text
persistent relational-capacity density = 0.
```

This is a type-separation theorem, not a claim that the second quantity has already been calibrated to physical stress-energy.

## 4. Gravity routes must remain separate

The two candidate routes are:

```text
A. response route
   DeltaLambda c_P
   -> Delta(deltaC)
   -> Time-Shell perturbative gravity.
```

and

```text
B. load route
   persistent relationships + Transition Capacity
   -> native rho_E
   -> UCM / stress-energy dictionary
   -> readable gravity.
```

The response route has the new uniform-state no-go.

The load route does not require realized flow, but its physical calibration and exact stress-energy handoff remain incomplete.

## 5. No double counting

If later work proves that one downstream stress-energy term already contains the perturbative redistribution contribution, the two branches must be combined with an explicit decomposition to prevent counting the same organization twice.

Until that dictionary is typed, they are maintained as distinct candidate channels.

## 6. Why this matters for the dark-matter program

A static-looking gravitational residual cannot be justified by saying merely that a hidden network "has flow" if its native continuity state is at equilibrium.

The Atlas must determine whether the relevant regime is:

```text
non-equilibrium / contrast-driven redistribution,
```

or

```text
persistent relational-capacity load,
```

or a typed combination of both.

This is now an explicit mathematical fork rather than an ambiguity hidden inside the word "load."

## Hard boundaries

```text
rho_E^R != automatically physical mass density
rho_E^R != automatically T_mn
zero flow != zero relationship
zero flow != zero capacity
nonzero capacity != automatically gravity
```
