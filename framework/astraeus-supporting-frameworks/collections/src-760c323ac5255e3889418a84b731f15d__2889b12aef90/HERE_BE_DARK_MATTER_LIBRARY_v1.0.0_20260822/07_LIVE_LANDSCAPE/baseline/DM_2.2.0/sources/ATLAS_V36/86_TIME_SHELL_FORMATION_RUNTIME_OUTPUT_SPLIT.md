# 86 — Time-Shell Formation / Runtime / Output Split

This module reconciles two apparently different API directions.

## Formation conditions

The upper dependency recovery states:

```text
Genesis Field
-> Resolution
-> Bandwidth
-> Inheritance
-> Occupancy
-> Persistence
-> Chirality
-> Boundary readability
-> Time-Shell candidate.
```

These describe **structural conditions under which an interface becomes admissible**.

## Runtime inputs

The linked dependency index states:

```text
ER foam  -> Time Shell
Graviton -> Time Shell.
```

These are interpreted as **operative substrate/mode inputs after the interface exists**.

## Outputs

The linked graph states:

```text
Time Shell -> Geometry
Time Shell -> Gravity.
```

Channel-specific branches refine this into configuration/readout and metric perturbation maps.

## Three-layer model

Define schematically:

```text
Form_TS = structural admissibility conditions
State_TS = operative substrate/mode state
Out_TS  = translated/projected readable organization.
```

Then

```text
Out_TS = T_TS(State_TS | Form_TS).
```

This is not a new source equation. It is an Atlas reconciliation rule that preserves all recovered edge directions without forcing them into a single causal chain.
