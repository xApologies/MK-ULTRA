# E011 — Resolution / Bandwidth / Rainbow-Road Retype

## 1. Correct the E010 Bandwidth language

The source definition is:

`Bandwidth = Available Organizational Freedom`.

Therefore E010's experimental integer `B` must **not** be called Bandwidth itself.

E010 `B` is retyped as:

`A_K = number of corridor relations allocated/retained by R5`

or, informally:

`allocated relationship slots`.

Source Bandwidth is the capacity that must be available to support this allocation:

`B_available >= Cost(K_selected)`.

The E010 result therefore does **not** say:

`physical Bandwidth >= 2`.

It says:

> in the controlled local topology stress, robust hidden information required the
> resolved state to retain at least two corridor relations.

This is a lower bound on **relational complexity / allocated capacity** in that sandbox.

## 2. Resolution ladder

The source definition is:

`Resolution = Distinguishable Organization`.

The E010 pairs give a clean finite example:

- `R0`: top-down occupancy + net chirality readout; the pair is not distinguished.
- `R1`: labeled local edge/adjacency relationships; every robust pair is distinguished.
- `R2`: complete 2x2x2 microstate; the pair remains distinguished.

So the hidden information is not ontologically absent.

It is unresolved at the coarse readout.

## 3. Rainbow Road

The mounted Rainbow Road source defines:

`Corridor = route`
`Portal = transaction over route`.

A two-corridor selected set is therefore not automatically a Rainbow Road.

However, when two selected corridor edges share a node, they form the smallest
composable path-like route in the local graph.

E011 tests whether E010's robust states have such route-capable B=2 selections.

This is only **route readiness**. Portal transaction typing, persistence contract,
Resolution/Bandwidth sufficiency, closure, residue, ancestry, and provenance remain
required before calling the result a successful Rainbow-Road transaction.
