# R4 Domain Specification
## Corridor Formation / Elastic Coupling

R4 is the first domain where a true corridor is allowed to form.

R3 may show proto-interaction awareness, but R3 does not stabilize the corridor.

R4 converts proximity response into bounded elastic topology coupling.

## Domain Role

R4 performs:

1. chirality readout
2. adjacency accommodation
3. elastic deformation
4. bounded continuity bridge initiation
5. corridor candidate construction
6. topology-preserving coupling

## What R4 Must Not Do

R4 must not:
- collapse the topology into final constrained forms
- enforce H2, N2, O2, or any element-specific result
- delete or eject manifolds
- perform survivability damping
- overwrite chirality

R4 only initiates and stabilizes corridor candidates enough for R5 to evaluate them.

## R4 Inputs

R4 receives:
- incoming manifold state from R3
- chirality readout fields
- adjacency continuity structure
- local shell deformation gradients
- corridor candidate map
- manifold ancestry register

## R4 Outputs

R4 emits:
- corridor candidate graph
- elastic coupling field
- chirality compatibility map
- topology strain pre-map
- preserved ancestry register
- unresolved shared ecology state

## R4 Interpretation

R4 asks:

Can these manifolds form a bounded continuity corridor without immediate topology collapse?

If yes, corridor candidates are emitted into R5.

If no, the manifolds remain weakly aware but non-coupled.
