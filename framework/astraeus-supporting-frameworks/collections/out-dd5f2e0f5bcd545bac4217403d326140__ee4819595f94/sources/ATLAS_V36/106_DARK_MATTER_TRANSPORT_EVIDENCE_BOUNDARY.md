# 106 — Dark-Matter Transport Evidence Boundary

## Critical boundary

The Tome's dark-matter bridge chapter preserves an explicit distinction:

```text
BridgeVocabulary != TransferOperator
NetworkFlow      != DarkMatterTransportLaw.
```

Therefore Atlas v12 does **not** invent a rate equation, diffusion law, transfer kernel, or capacity constant merely because graph mathematics is available.

## Recovered / available scaffold

Standard network bookkeeping may be used for cartography:

```text
G_ER = (V,E,w,l,tau)
adjacency matrices
weighted degree
graph neighborhoods
graph Laplacians
coarse-graining.
```

But physical interpretation requires a separately typed map.

## Open transport obligations

Before a dark-matter transport law can be promoted, recover or derive:

```text
1. transported quantity
2. source and target endpoint types
3. corridor / bridge kernel
4. update or rate law
5. capacity / Bandwidth units
6. causality / ordering proof
7. conservation proof
8. cosmological embedding
9. gravitational / stress-energy handoff
10. discriminating prediction
11. external validation protocol.
```

## v12 rule

Cartography may map the network **before** dynamics are claimed.

This is intentional. First establish what is connected and how the existing objects are typed; only then ask what is physically transported.
