# 07 — Time Shell as Persistent History-Readout Boundary

The Time Shell is modeled as more than a static surface. It is the persistent boundary/translation structure by which a History-bearing organization acquires a localized readable address.

## 1. Typed working object

Define the local Time-Shell object

```text
TS = (
  dXi,
  Lambda_chi,
  Pi_TS,
  Read_R,
  Ord,
  Inv
).
```

Roles:

- `dXi` — persistent boundary;
- `Lambda_chi` — chirality-coupled localization action;
- `Pi_TS` — projection from persistent-boundary organization to local readable projection;
- `Read_R` — Resolution quotient/readout;
- `Ord` — ordering-label map on persistent History;
- `Inv` — recoverable invariant residue.

This tuple is an Atlas typing, not a recovered whole-object identity from the Tome.

## 2. History-bearing shell address

A Time-Shell address is

```text
TSAddress = (
  Sigma_p,
  b,
  [h]_Id,
  chi,
  Inv,
  R,
  B,
  O
)
```

where `b in dXi` is a persistent-boundary representative and `[h]_Id` is the relevant Identity-through-History class.

This extends the existing Chirality Address by making History identity explicit.

## 3. Formal vs readable shell

Two Time-Shell occurrences may satisfy

```text
same Formal Identity,
different Read_R presentation.
```

Conversely, a closed readable presentation does not guarantee the same Formal Identity because History holonomy may be nontrivial.

## 4. Persistence-before-time principle

The pipeline evidence supports the sequence

```text
chirality
 -> adjacency
 -> propagation
 -> persistence
 -> interaction history
 -> temporal behavior.
```

Accordingly, the Atlas does not make clock time primitive. Readable time is an ordering representation of persistent/history-bearing structure.
