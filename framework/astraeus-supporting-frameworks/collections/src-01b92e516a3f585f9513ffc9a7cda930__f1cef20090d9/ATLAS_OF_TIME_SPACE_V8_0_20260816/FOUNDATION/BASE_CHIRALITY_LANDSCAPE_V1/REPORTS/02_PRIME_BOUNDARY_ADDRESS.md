# Prime Boundary -> Address -> Geometry

## Prime rule

```text
Z = 0_L | 0_R
0_L ==_Id 0_R
0_L !=_pos 0_R.
```

The pipe is a boundary relation. The same identity is locally addressable from two positions.

## Generalized boundary-address principle

For identity class `[x]`, a boundary presentation may generate multiple address occurrences:

```text
x -> (x_L, x_R)
```

while preserving:

```text
id(x_L) = id(x_R) = id(x).
```

The induced distinction is representational/local rather than ontological.

## Geometric realization

For a local 3-domain `B_i^3`:

```text
Sigma_i = boundary(B_i^3) ~= S2.
```

`Sigma_i` separates the local neighborhood from its complement in the S3 carrier and therefore functions as a localized address boundary.

## Time-Shell interpretation

The boundary itself need not be a material shell. Time Shell is modeled as the persistent translation/readout machinery associated with the boundary:

```text
address boundary
-> local lift
-> invariant/history transport
-> projection/readout.
```

This keeps:

```text
boundary relation
!=
material boundary object
```

while allowing the boundary to be mathematically operational.
