# VERA AUDIT PROTOCOL — CHIRALITY FUSION ROADMAP v1.0

## Purpose
Prevent circular proof, recursive restatement, type collapse, provenance loss, and terminology-driven conclusions.

## Mandatory audit questions for every run

1. What exact premises entered the run?
2. Which premises are SOURCE, DERIVED, CANDIDATE, or HYPOTHESIS?
3. Did the conclusion appear earlier disguised as a definition?
4. Was any visual analogy used as proof?
5. Was an endpoint substituted for a path/history claim?
6. Was classical correlation mislabeled as coherence or entanglement?
7. Was entanglement mislabeled as fusion?
8. Was the uniqueness of `∅` preserved?
9. Were address labels or relational positions confused with set content?
10. Were A and B treated as post-fusion subsystems without R02 authority?
11. Did any projection/readout change get mislabeled as underlying-state corruption?
12. Were counterexamples attempted?
13. What would falsify the current candidate?
14. Is each page/section doing a distinct mathematical job?
15. Does the run have a genuine exit verdict?

## Stop rule
If any required premise is missing, mark the run PARTIAL or BLOCKED. Do not manufacture the premise downstream.
