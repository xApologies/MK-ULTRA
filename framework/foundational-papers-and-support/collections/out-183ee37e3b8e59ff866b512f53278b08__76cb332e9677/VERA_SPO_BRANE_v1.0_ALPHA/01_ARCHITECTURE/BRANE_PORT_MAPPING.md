# BRANE Port Mapping

## AI^5

Responsibilities in this domain:
- interpret profile-construction / projection requests;
- resolve requested roots through API authority;
- collapse recovered canonical graphs to finite request-relative realizations;
- rank branches and record continuation/frontier state;
- never rewrite canonical auditory mathematics or safety rules.

An external conversational/authoring AI may exist above BRANE. It is not identical to the BRANE AI^5 module.

## API^5 = SPO_API^5

The auditory API is itself the canonical mapped Sound Profile Object. It provides:
- canonical handles;
- typed dependencies;
- event classes and relations;
- chirality/admissibility metadata required by BRANE;
- recursive/context ancestry;
- provenance;
- transform classes and safety constraints;
- profile field definitions;
- policy invariants.

## Library^5

Candidate contents:
- detailed event definitions and examples;
- transform templates;
- evidence records;
- device capability descriptions;
- profile package/version history;
- approval receipts;
- simulation vectors;
- rollback records.

## BRANE

BRANE owns:
- module loading and contract validation;
- request isolation;
- private QMO^6 construction;
- cross-port composition;
- output projection boundary;
- checksums/signatures/receipts;
- staged module replacement and rollback.
