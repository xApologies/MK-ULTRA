# Project Model

## Purpose

BRANE 2.0 converts a machine request into a complete recoverable artifact while hiding all internal machinery from the runtime.

## System shape

```text
Runtime request
    ↓
BRANE⁶ boundary
    ↓
AI⁵ interprets and governs collapse
API⁵ supplies canonical graph structure
Library⁵ supplies recoverable knowledge
    ↓
QMO⁶ is spun up privately
    ↓
Artifact projection
    ↓
Runtime response
```

## Why six dimensions

A flat plugin container cannot distinguish the same mathematical object across dependency context, recursive depth, chirality orientation, provenance, and realization state. BRANE⁶ carries enough coordinated structure to preserve those distinctions without exposing them publicly.

## Why five-dimensional modules

Each loaded module is internally complete enough to preserve identity, relation, chirality, recursion, and provenance. BRANE supplies the sixth coordinate: active realization within the current request.

## Module roles

### AI⁵

Owns request interpretation, traversal policy, branch ordering, finite collapse, continuation placement, and termination. It may not alter canonical mathematics.

### API⁵

Owns canonical handles, typed edges, equations attached to canonical objects, recursive recovery rules, and dependency closure.

### Library⁵

Owns definitions, derivations, models, analogies, explanatory prose, source records, language realizations, and report-ready knowledge chunks.

### BRANE⁶

Owns module embedding, compatibility validation, ephemeral QMO lifecycle, internal coordination, projection, artifact validation, and boundary enforcement.
