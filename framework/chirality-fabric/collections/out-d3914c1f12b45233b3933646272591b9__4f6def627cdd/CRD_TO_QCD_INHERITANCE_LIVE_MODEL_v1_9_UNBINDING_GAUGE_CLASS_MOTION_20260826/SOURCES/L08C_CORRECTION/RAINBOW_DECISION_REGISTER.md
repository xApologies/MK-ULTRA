# Decision Register

## DR-001 — Active system target

**Decision:** The active engineering target is the Genesis Mainframe.  
**Long-term application:** VÆLD-class ship.  
**Reason:** The mainframe is the prerequisite control, computation, memory, language, and intelligence architecture.

## DR-002 — Not a prototype request

**Decision:** Do not substitute a small GPT-built emulator for the requested architecture map.  
**Clarification:** Reference implementations may later test semantics but are not the architecture.

## DR-003 — Compute Trinity

**Status:** Canonical.

```text
Stored Geometry
Active Geometry
Observed Geometry
```

These are perspectives of one recursively dynamic topology.

## DR-004 — Persistent storage role

**Status:** Working architectural lock.

The persistent hardware tier establishes the initial configuration space for the chirality fabric. It must physically retain basin and chirality organization rather than merely store a conventional file that describes them.

## DR-005 — Structural basins

**Status:** Canonical requirement; physical realization open.

```text
Red     1/7
Orange  2/7
Yellow  3/7
Green   4/7
Blue    5/7
Violet  6/7
```

The basin is treated as structural organization. Exact device-level voltage windows, materials, and error margins remain open.

## DR-006 — Hard-stop and rotational basin views

**Status:** Both preserved.

The hard-stop basin is a distinct structural identity. The `142857` family may encode a cyclic or rotational grammar. Neither view is allowed to erase the other.

## DR-007 — Chirality object

**Status:** Canonical.

Chirality is an admissibility/organizational grammar. The `2 x 2 x 2` chirality byte is arrangement-first.

## DR-008 — Geometric location

**Status:** Working lock.

Geometrics are instantiated operational objects of the software/operating topology. They are realized on and constrained by the physical chirality fabric.

## DR-009 — Genesis language location

**Status:** Working lock.

Genesis is the architecture-native language spanning semantic intent, geometric organization, runtime transformation, and Guardian oversight. It is neither merely machine code nor merely a top-level language, and it is not defined by a JVM.

## DR-010 — Guardian availability

**Status:** Open research program.

The required Guardian Intelligence does not currently exist as a completed system. It must be designed and trained to organize geometrics, navigate chirality configuration space, operate portals, preserve identity, and supervise closure/recovery.

## DR-011 — Portal

**Status:** Working lock.

```text
Corridor = admissible route
Portal   = transaction over the route
```

The portal is the native bus of the Genesis Mainframe.

## DR-012 — Portal evidence boundary

**Status:** Locked.

The hydrogen artifact demonstrates a computational information-preservation layer: encode, transform, recover, verify. It does not yet prove a physical portal substrate.

## DR-013 — Physical versus organizational energy

**Status:** Working lock.

Physical hardware uses ordinary measurable energy. MK-43 organizational energy tracks changes in persistence/organization. A future calibration map must connect the two.

## DR-014 — 3+1+1 axis naming

**Status:** Open.

Recovered forms include:

```text
XYZ + Set-Lift + Chirality
XYZ + Chirality + Inheritance/History
```

Use neutral notation `XYZ + L + Chi` until the relation is formally reconciled.

## DR-015 — White and black

**Status:** Open.

White and black are not automatically ordinary seventh and zero basin values. Their executable semantics remain unresolved.

## DR-016 — Language-first architecture

**Status:** Locked project direction.

The Genesis programming language is now the organizing spine of the mainframe project.

Hardware, operating topology, portals, and Guardian Intelligence must conform to the language semantics.

## DR-017 — Portal as first mandatory language primitive

**Status:** Working lock.

The language must contain a first-class `portal` construct.

A portal declaration must include or derive:

```text
source
target
payload
identity preservation
chirality transport
capacity requirements
closure target
failure recovery
provenance
```

The compiler/Guardian must reject underdefined portals rather than inventing silent defaults.


## DR-018 — Anecdotal placeholders

**Status:** Locked correction.

Names used casually in anecdotes must not become architectural identifiers or canon terms without explicit approval.

“Claire” was removed from the Genesis programming-language examples and replaced with neutral payload terminology.

## DR-019 — Candidate primitive data type

**Status:** Active working hypothesis.

The current candidate primitive data type of Genesis is the Geometric.

A Geometric is provisionally a populated `3+1+1` chirality-organized manifold.

This is not yet a final type-system lock.

## DR-020 — Colored chirality byte

**Status:** Active working model.

A `2 x 2 x 2` chirality byte may carry local structural-basin values at occupied sites.

The byte has:

```text
occupancy/chirality arrangement
site-level basin distribution
derived byte-level color
```

The derived color does not replace the underlying distribution.

## DR-021 — Same aggregate, different Geometric

**Status:** Locked distinction.

Two chirality bytes may resolve to the same aggregate color while remaining structurally distinct.

Resolution determines whether they are considered equivalent for a particular operation.

## DR-022 — Portal-first, not portal-only

**Status:** Locked development method.

The portal is the first handle used to discover Genesis language requirements.

It is not the whole language.

## DR-023 — Language remains pre-formal

**Status:** Locked correction.

No final Genesis syntax, loop system, function model, compiler, or portal syntax has been established.

Existing grammar and code-like examples are provisional sketches.

## DR-024 — Physical voltage mapping

**Status:** Open.

The project does not yet define exact voltages for Empty or for the six basin states.

The language-level basin semantics must remain separable from a future physical realization.

## DR-025 — Color classes

**Status:** Active working model.

Each structural basin defines a class of Geometrics that resolve into that color.

```text
Gamma_k = { G | Color(G) = B_k }
```

Members of one color class may remain structurally distinct.

## DR-026 — Color-indexed portals

**Status:** Active working model.

Portals may use structural basin color as a discrete admission or routing index.

Candidate behaviors include:

```text
color-gated
color-preserving
color-transforming
color-multiplexed
```

Color is not the entire portal contract. Chirality, identity, Resolution, Bandwidth, and closure may impose additional conditions.

## DR-027 — Full payload preservation

**Status:** Locked distinction.

A color-specific portal selects a class of Geometrics. It does not reduce the transported payload to a color label or aggregate basin value.

## DR-028 — Rainbow Road

**Status:** Active working model.

A Rainbow Road is a persistent route composed from color-indexed portal segments.

```text
Portal = edge / transaction
Rainbow Road = path / inherited route
```

## DR-029 — Road and bus distinction

**Status:** Active working model.

```text
Rainbow Bus
    available color-indexed transport capacity

Portal
    one transport transaction

Rainbow Road
    persistent navigable route through portal composition
```

## DR-030 — Basin order remains open

**Status:** Open.

The project does not yet choose whether Rainbow Road traversal follows:

```text
spectral basin order
142857 rotational order
local admissibility
Guardian selection
explicit program order
```
