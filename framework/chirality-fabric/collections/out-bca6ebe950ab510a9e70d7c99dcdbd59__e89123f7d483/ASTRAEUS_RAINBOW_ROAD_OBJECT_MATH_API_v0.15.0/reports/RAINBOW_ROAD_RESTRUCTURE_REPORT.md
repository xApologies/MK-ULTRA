# Rainbow Road Recursive Runtime Restructure — v0.2.0

## Decision

Astraeus Object Mathematics API is restructured so Rainbow Road is the active dynamic recursive closure domain and the Möbius carrier supplies its local return/orientation structure.

The API is no longer modeled as an external database that merely queries Rainbow Road. The registries, derivations, Resolution readouts, Bandwidth availability, Identity/History witnesses, and closure state are presentations inside one recoverable domain.

## Closure state

`Cl_RR(X)` is the semantic closure operator. It is intended to be extensive, monotone, and semantically idempotent while the domain contract is unchanged.

History is intentionally not idempotent: a traversal can return to the same local presentation while adding a new recoverable History token.

## Internal promotion

The v0.1 blanket prohibition on automatic promotion is superseded.

A result may self-promote when a machine-auditable Closure Certificate establishes that it is an internal consequence of admitted objects and licensed transformations, remains inside the current domain, preserves provenance/recovery requirements, and passes hard guards. Domain-changing claims remain audit-gated.

Initial closure smoke test self-promoted: @history_bearing_return, @return_not_reset.

## Perturbation engine

Perturbations run only in isolated branches. The engine computes a recursive impact cone, hard-guard conflicts, and closure certificates requiring revalidation. A perturbation fixed point never overwrites canonical mathematics by itself.

The pink-sky analogy is typed in two forms:

1. **readout-only:** change the displayed sky label; no unrelated upstream rewrite follows automatically;
2. **constraint-change:** change a shared upstream environmental constraint; every dependent structure enters the impact cone and must be re-evaluated under licensed rules.

This preserves the useful intuition—recursive changes can propagate rapidly—without assuming that an arbitrary observation rewrite physically changes unrelated objects.

## Safety/logic caveat

Recursive amplification is a consistency probe, not a truth oracle. A wrong premise can sometimes generate an internally consistent wrong model. Conversely, a contradiction can explode under classical logic but need not under every logic. The runtime therefore reports defects, forks, and provenance rather than equating 'large blast radius' with falsity.
